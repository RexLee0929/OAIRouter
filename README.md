# OAIRouter

**本机运行的 OpenAI 兼容网关：多上游路由 + Chat Completions ↔ Responses 协议翻译。**

客户端只要会说 `/v1/chat/completions`，就能经它访问只提供 Responses API 的模型；还能查看用量和花费。服务在本机监听，请求仍会发送给所配置的上游。

## 30 秒上手

1. 安装后运行程序，路由列表已经带一条默认路由：`openai → https://api.openai.com`
2. 把上游地址改成你要用的（OpenAI 官方、各家中转都行），前缀就是地址里那一段
3. 点「启动服务」，点旁边的「复制地址」拿到 `http://127.0.0.1:8787`
4. 在客户端把 API 地址填成 `http://127.0.0.1:8787/openai/v1`，模型名与 API 密钥照常填
5. 「请求统计 → 用量」里看每个模型花了多少 token、多少钱

## 它解决什么

| 问题 | 直接用会怎样 | 本程序 |
|---|---|---|
| 新模型只提供 Responses API，客户端只会说 Chat Completions | 客户端直连报错，或 function tools 与 reasoning 参数打架 | `responses` 模式把请求与流式响应整体翻译，工具调用原样带过去 |
| 多个上游来回换，每次都改客户端的 base_url | 配置改来改去，容易填错 | 前缀路由：一个地址 `http://127.0.0.1:8787/<前缀>/v1` 对应一个上游 |
| 客户端连通性探测常发 `max_tokens: 1` | 回答只有几个字，看不出模型真实表现 | `responses` / `rewrite` 模式可按输出 token 上下限调整 |
| 花了多少钱没处看 | 各家中转后台口径不一，官方后台要登网页 | 价格表 + 用量统计，按模型 / 路由 / 会话 / 时间直接算金额 |
| 模型名又长又不统一 | 客户端里手敲全名还容易拼错 | 模型映射：别名 → 真实模型名，客户端里填短名就行 |

## 功能

| 功能 | 说明 |
|---|---|
| 前缀路由 | `http://127.0.0.1:8787/<前缀>/...` 转发到对应上游；没匹配上走默认路由（前缀留空或 `*`），再没有就返回明确的 404 |
| 三种模式 | `responses` 翻译成 Responses API / `chat` 不做协议翻译或参数改写 / `rewrite` 参数改写；路由级设置，单个模型可单独覆盖 |
| 模型映射 | 客户端填的模型名 → 实际转发的模型名，可逐模型指定模式（区分大小写） |
| 用量统计 | 每条请求记 token（含缓存读 / 写）、耗时、状态；按模型 / 路由 / 会话 / 时间分组，支持时间范围筛选和 CSV 导出 |
| 上游配置 | 设置上游类型、余额查询和可选密钥映射；密钥使用 Windows DPAPI 保护 |
| 价格表 | 输入 / 输出 / 缓存读 / 缓存写单价（美元 / 百万 token），支持按输入长度分挡、按每天时段生效、按日期过期 |
| 价格同步 | 从已配置上游、LiteLLM 社区价格表或受支持的自定义 JSON 地址拉价格，确认后并入价格表 |
| 运行日志 | 记录请求状态、耗时与错误摘要；可选开启实验性诊断，分享日志前请检查敏感信息 |
| 托盘常驻 | 点关闭进托盘不退出，双击图标恢复；支持开机自启（登录后自动在托盘运行，不自动启动服务） |
| 配置导入导出 | 导出完整配置；导入时可勾选路由、映射、价格表、模型库和设置 |
| 安装 / 卸载 | 6 页中文向导，升级默认保留配置；支持静默安装；卸载可保留个人数据 |

## 选项说明

| 选项 | 默认值 | 说明 |
|---|---|---|
| 端口 | 8787 | 服务只监听 `127.0.0.1`，可改 1024–65535 |
| 输出 token 下限 | 16 | `responses` / `rewrite` 模式下，输出 token 限制低于此值时会被抬高 |
| 输出 token 上限 | 0（不限制） | `responses` / `rewrite` 模式下，设定后将输出 token 限制压到该值 |
| 客户端 | Auto | 自动识别依赖请求中可观察到的标识；也可选择 WorkBuddy 或 DeepSeek Harness |
| 实验性诊断 | 关 | 开启后写入独立诊断日志；用于排查识别与请求结构，不记录对话正文或密钥 |
| 开机自启动 | 关 | 写当前用户注册表 Run 键，登录后以托盘方式运行 |
| 自动滚动日志 | 开 | 「视图」菜单切换 |
| 日志条数上限 | 800 | 界面里保留的日志行数；在 `config.json` 里改 `LogLimit` |

所有设置存在安装目录的 `config.json`，界面改动约 1 秒内自动落盘；每次启动还会在 `backups/` 留一份快照，最多保留 10 份。

## 安装

向导共 6 页：欢迎 → 安装模式 → 许可协议 → 安装位置 → 附加任务 → 准备安装。

- **仅为我安装**（推荐）：`%LOCALAPPDATA%\Programs\OAIRouter`，无需管理员权限
- **为所有用户安装**：请求一次 UAC，装到 `%ProgramFiles%\OAIRouter`
- 附加任务：桌面快捷方式（默认勾）、开始菜单快捷方式（默认勾）、开机自启（默认不勾）、立即运行（默认勾）
- 升级 / 重装时默认**保留现有配置**；想恢复默认就勾「覆盖现有配置」
- 静默安装：`OAIRouter-<版本>-setup.exe --silent`，用默认目录装，不改现有配置

**文件位置**（都在安装目录下）

| 文件 / 目录 | 内容 |
|---|---|
| `config.json` | 设置、路由、映射、价格表、模型库及经 Windows DPAPI 加密的上游凭据 |
| `usage.jsonl` | 用量记录，一行一条，含时间、路由、模型、会话标识、token、耗时和状态，不含对话正文；分享前请检查 |
| `logs\app.log` | 运行日志，超 2 MB 轮转为 `app.log.1` |
| `logs\diagnostics.log` | 开启实验性诊断后写入的独立日志；分享前请检查 |
| `backups\` | 每次启动的配置快照，最多 10 份 |

卸载时默认勾选「保留个人数据」，`config.json`、`usage.jsonl`、`logs`、`backups` 会留下，重装后自动沿用。

**系统要求**：Windows 10 / 11（x64），约 80 MB 磁盘空间。程序自带 .NET 运行时，不需要另外安装。

## 路由与计价机制

**路由匹配**：取 URL 路径第一段作前缀（忽略大小写），匹配路由表；前缀留空或 `*` 的路由是默认路由，整条路径原样转发。`/v1` 会自动去重——上游地址以 `/v1` 结尾、客户端又请求 `/v1/...` 时不会拼出两份。

**三种模式**：

- `responses`：把 `/chat/completions` 请求翻译成 Responses API 转发到 `{上游}/v1/responses`。system / developer 消息合并为 `instructions`，工具调用双向转换；`reasoning_effort` 的 `none` 会删掉、`xhigh` / `max` 按最高档 `high` 发送（Responses API 没有更高档）；`max_tokens` 换算为 `max_output_tokens` 并按上下限夹取。流式请求逐事件翻译 SSE，客户端拿到的仍是标准 Chat Completions 流。当请求含 `reasoning` 且上游返回 400、错误内容符合不支持该参数的判断时，会去掉该参数重试一次并记录日志。
- `chat`：不做协议翻译或参数改写，但请求体里的 `model` 可能换成映射后的真实模型名；请求头也并非全部转发。
- `rewrite`：仍走 `/chat/completions`，改写参数——带工具调用时把 `reasoning_effort` 压成 `none`、`max_tokens` 迁移为 `max_completion_tokens`，并按输出 token 上下限夹取。

**鉴权与上游配置**：在「上游配置」中添加或编辑上游，可填写余额查询令牌、实际的上游 API Key 和可选的客户端本地 API Key。上游 API Key 留空时透传客户端 `Authorization`；填写后转发时使用该上游密钥，若同时设置本地 API Key，客户端须使用匹配的 Bearer 密钥，否则拒绝转发。`OpenAI-Organization`、`OpenAI-Project` 头也会转发，其他请求头不保证转发。包含认证信息的请求仅允许发送到 HTTPS 或本机 HTTP 地址。

配置中的密钥使用 Windows DPAPI 加密，通常与当前 Windows 用户环境关联；复制配置到其他账户或设备后可能无法解密，需要重新输入。配置导出和备份也包含加密后的凭据，仍应妥善保管。

**余额与价格同步**：在上游编辑窗口选择 NewAPI、OpenAI 或自定义类型并填写需要的查询设置。NewAPI 的余额地址留空时使用上游地址的 `/api/user/self`；自定义接口需要填写地址和返回数值的 JSON 路径。OpenAI 官方普通 API Key 没有通用余额查询接口。价格同步支持 NewAPI、LiteLLM 及程序支持的自定义 JSON 格式；选中上游时可按类型使用或复用余额查询凭据，发送凭据受同源和 HTTPS（本机可用 HTTP）限制。

**计价**：单价单位是美元 / 百万 token，分输入、输出、缓存读、缓存写四项；未缓存的输入按「max(0, prompt − 缓存读 − 缓存写)」计。规则匹配时依次优先精确路由、精确模型、限定时段和起点大于 0 的挡位；评分相同时优先挡位起点较高的规则，仍相同则按表中顺序。没有匹配规则时不计价（用量页显示「无价格」）。

**模型与计价**：用量按客户端填写的模型名分组，按转发给上游的真实模型名匹配价格；旧记录没有真实名时回退使用记录中的模型名。模型库可手动维护或通过「从用量导入」补充真实模型名。

**会话与上限**：程序从请求头 `X-Conversation-ID` 或请求体指定元数据位置读取有效的 D / N 格式 GUID，以会话标识摘要分组；没有有效标识的请求归为「未识别会话」。会话可展开查看请求标识分组；部分符合条件的关联会标注为推断，不能保证等同于用户对话轮次。旧记录可能保留旧格式的会话标识，部分历史诊断可用于只读推断。`X-Conversation-ID` 头不转发给上游，但请求体仍按转发模式处理。统计在内存中保留最近 2 万条，启动时从 `usage.jsonl` 的末尾载入；文件持续追加，不会按此上限自动截断。

**筛选与导出**：「用量」的模型、路由和会话分组可选全部时间或过去 1 小时至 30 天；时间分组使用时间桶粒度。点击「导出」保存当前内存中请求明细的 CSV，导出范围与当前筛选对应；时间分组不应用范围筛选。CSV 及用量记录可能包含敏感的使用元数据，分享前请检查。

## 常见问题

**API 地址到底怎么填？**
`http://127.0.0.1:8787/<路由前缀>/v1`。比如前缀 `openai`、上游 `https://api.openai.com`，就填 `http://127.0.0.1:8787/openai/v1`。点「复制地址」可以直接拿端点。

**我的 API 密钥存在哪里？**
默认透传客户端的 `Authorization`；如在上游配置中填写密钥，配置文件保存的是经 Windows DPAPI 加密的密钥。日志可能包含上游错误片段或异常信息，仅对符合 `sk-` 特定格式的内容做正则脱敏，不保证覆盖所有密钥；分享日志前请检查。

**客户端报「模型不存在」，或上游报「No available channel」？**
请求里的模型名在上游不存在。加一条模型映射把客户端填的名字换成真实模型名；注意映射**区分大小写**（路由前缀不区分，两处行为不一样）。

**为什么测试请求返回的内容比预期长（或被截断）？**
在 `responses` / `rewrite` 模式下，输出 token 下限可能把探测请求的 1 抬到 16；设置上限也会限制输出。按需调整这两个数；`chat` 模式不做此调整。

**上游返回 524 怎么办？**
524 是上游返回的超时响应，日志会提示联系上游服务商排查；程序不会针对 524 自动重试。流式输出是否实时也受客户端和上游服务影响。

**为什么有的请求报 `route_not_found`？**
URL 路径第一段没匹配任何路由前缀，也没有默认路由。加一条前缀留空或 `*` 的路由兜底。另外客户端若开了「自定义路径」之类不自动补 `/chat/completions` 的选项，请求会落在裸路径上，日志会提醒你关掉该选项。

**双击图标怎么没开新窗口？**
程序单实例运行：再次启动只是把已运行的窗口唤到前台，不会开第二个。双击托盘图标同理。

**对话内容会被记录吗？**
用量记录不保存对话正文，但日志可能包含上游错误片段或异常信息，其中可能出现对话内容或其他敏感数据，分享前请检查。请求本身会转发到配置的上游，并非只留在本机。

**重装或升级会丢配置吗？**
不会，安装向导默认保留 `config.json` 等个人数据；误改了配置可以从 `backups/` 里翻最近 10 份快照。

## 已知限制

- 只支持 Windows 10 / 11（x64）；标题栏配色走 DWM，老系统自动退回默认外观。
- 服务只监听 `127.0.0.1`，局域网其他设备访问不到。
- 只有 `/chat/completions` 会按模式进行协议翻译或参数改写；其他 JSON 端点也可能替换请求体中的 `model`。
- 模型名映射区分大小写，路由前缀不区分——两处口径不一致，配的时候留意。
- 模型库不从上游拉取，手动维护或用「从用量导入」。
- 价格表匹配不上的请求不计价，不会估一个近似值；不同上游协议的缓存 token 口径可能不同，其他协议的缓存归一化尚未单独验证。
- 会话识别依赖客户端提供有效标识；推断关联和请求标识不保证等同于用户对话轮次。
- OpenAI 官方普通 API Key 没有通用余额查询接口；查询能力取决于所配置上游及接口。
- DPAPI 保护的密钥可能无法在其他 Windows 账户或设备解密，迁移后可能需要重新输入。
- 「为所有用户安装」时装在 Program Files，配置与用量数据也写在安装目录，普通权限下可能写不进去——推荐用「仅为我安装」。
